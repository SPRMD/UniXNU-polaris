# Polaris WOA evidence and Darwin porting boundary

The local `external/woa-polaris` checkout is useful because it describes which
pieces of the MIX 2S hardware have been exercised on Windows on ARM.  The
checklist is evidence about the board and its firmware wiring; it is not a
Darwin driver ABI and it does not make an iOS image flashable.

At the recorded WOA revision, the checklist marks these functions as working
on Windows: battery status, Bluetooth, brightness, LTE, USB charging, wireless
charging, display, GPU (without x64 acceleration), touchscreen, UFS, USB,
Wi-Fi, accelerometer, GPS, gyroscope, light and proximity sensors, and NFC
tags.  Audio, camera, flashlight, SMS and fingerprint remain unchecked.  NFC
is explicitly limited to tags, so it is not evidence that secure-element or
payment flows work.

The corresponding WOA-Drivers tree contains board-specific or SDM845 inputs
for the following paths:

| WOA evidence | Polaris port use | Darwin state |
| --- | --- | --- |
| `SynapticsTouch.sys` and `SynapticsTouch.inf_` | RMI4/S3708 identity and bounded frame/protocol reference | Requires a new board-gated I2C/GPIO/IRQ/IOHID service |
| `qcwlan850.sys`, `bdwlan.*`, WCN configuration | WCN3998/WCN3990 firmware naming and resource evidence | Requires a Darwin transport, firmware loader and network stack integration |
| `qcbtfmuart850.sys`, `crbtfw*.tlv`, `crnv*.bin` | WCN3998 UART/H4 firmware candidates | Requires a Darwin UART/HCI service and power sequencing |
| `qcbattmngr850.sys` | PMI8998 fuel-gauge wiring and battery property names | Requires a Darwin SPMI/PMIC power source |
| `qccam*`, IMX363 tuning files | Camera sensor and CAMX resource names | Requires a Darwin CCI/CSIPHY/CSID/ISP stack |
| `qcdxkm850.sys`, `qcvss850.mbn` and A630 inputs | Adreno/GMU firmware provenance | Requires A630 GMU/HFI, power, SMMU, CP and rendering backends |
| NXP NFC binaries | NCI/PN54x device-family reference | Requires board-confirmed wiring and a Darwin NCI service |

Windows `.sys`, `.dll`, `.mbn`, `.bin`, `.tlv` and firmware files cannot be
loaded as XNU kexts or iOS userland drivers.  The importer therefore records
only names, sizes, revisions and hashes.  A driver can move from evidence to a
flashable package only after its Darwin source is built, linked into the target
prelink/rootfs, and validated by a bounded temporary Polaris boot.

The machine-readable copy of this evidence is generated by
`scripts/import-polaris-woa-evidence.py`.  It includes a SHA-256 of the WOA
status checklist and the parsed checkbox state while keeping the package gate
at `flashable=false`.
